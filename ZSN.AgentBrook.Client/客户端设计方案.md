## Context

ZSN.Knowbase 平台当前有一个 WPF 桌面客户端 (ZSN.Knowbase.APP)，仅支持 Windows，技术栈老旧，维护成本高。需要基于 Tauri + Vue3 构建新版跨平台桌面客户端，同时让 ZSN.AgentBrook.Client (.NET) 作为 SPA 静态文件宿主支持浏览器访问，实现一份前端代码、两种部署模式。

**目标**: 快速开发、跨平台支持 (Windows + Mac)、低维护成本、复用现有 Vue-ChatBox 对话组件。

**设计原则**:
- **前后端分离** — 前端直连 API 服务，.NET 宿主仅做静态文件托管，不做 API 代理
- **平台适配抽象** — 通过 Adapter 层统一封装 Tauri/Web 的差异能力
- **安全优先** — Token 安全存储、传输加密、XSS 防护
- **容错设计** — 断线重连、消息队列、优雅降级
- **性能优先** — 虚拟滚动、懒加载、Bundle 分割

### 双模式部署

| 模式 | 说明 | 宿主 | 前端访问 API 方式 |
|------|------|------|-----------------|
| **桌面端** | Tauri 打包为原生应用，嵌入前端资源 | Tauri (Rust) | 直连远程 API |
| **Web 端** | .NET/Nginx 提供 SPA 静态文件托管 | ZSN.AgentBrook.Client (.NET) | 直连远程 API |

两种模式共享同一份 Vue3 前端代码，构建后分别嵌入 Tauri 和复制到 .NET `wwwroot/`。前端通过配置的 `API_BASE_URL` 直连后端 API，**不通过 .NET 宿主做 API 代理**（减少中间层，降低延迟和维护成本）。

### 为什么不做 API 代理？

| 方案 | 优点 | 缺点 |
|------|------|------|
| ❌ .NET 做 YARP 代理 | 统一入口 | 增加延迟、增加运维复杂度、.NET 项目职责不清 |
| ✅ 前端直连 API | 更快响应、架构简单 | 需配置 CORS (API 已支持) |

## 2. 技术栈

| 层次 | 技术 | 版本 | 用途 |
|------|------|------|------|
| 桌面壳 | **Tauri** | 2.x | 跨平台桌面应用框架 |
| 前端框架 | **Vue 3** | 3.5+ | Composition API + TypeScript |
| UI 组件库 | **Element Plus** | 2.x | 基础 UI 组件 (自定义对话风格主题) |
| 构建工具 | **Vite** | 6.x | 快速构建 + HMR |
| Markdown | **marked.js** + **highlight.js** | - | 对话内容渲染 (复用 Vue-ChatBox) |
| HTML 安全 | **DOMPurify** | - | XSS 防护 |
| 加密 | **Web Crypto API** + 兼容封装 | - | AES-CBC 加密 + SHA-256 签名 |
| 状态管理 | **Pinia** | 2.x | 全局状态 (含持久化插件) |
| 路由 | **Vue Router** | 4.x | 页面路由 |
| HTTP | **Axios** | 1.x | API 通信 + 请求重试 |
| 虚拟滚动 | **@tanstack/vue-virtual** | - | 长列表性能优化 |
| 语音识别 | FunASR Server | - | 通过后端 WebSocket 代理访问 |
| 音频处理 | Web: AudioWorklet / 桌面: FFmpeg (sidecar) | - | 音频格式转换 |
| 后端宿主 | **ASP.NET Core** | 10.0 | SPA 静态文件托管 |

### 技术选型变更说明

| 变更项 | 原方案 | 新方案 | 原因 |
|--------|--------|--------|------|
| 加密库 | CryptoJS | Web Crypto API | CryptoJS 已停止维护，Web Crypto 原生更安全 |
| ASP.NET | 8.0 | 10.0 | 与项目其他模块保持一致 |
| FunASR 连接 | 前端直连 | 后端代理 | 避免暴露内部服务地址 |
| 长列表 | 无 | @tanstack/vue-virtual | 1000+消息场景性能保障 |

## 4. 平台适配层设计

### 核心思想

通过 Adapter 模式抽象平台差异，业务代码调用统一接口，无需关心运行在 Tauri 还是浏览器。

```typescript
// platform/adapter.ts - 适配器接口
interface PlatformAdapter {
  // 存储
  secureStorage: {
    get(key: string): Promise<string | null>
    set(key: string, value: string): Promise<void>
    remove(key: string): Promise<void>
  }
  // 文件系统
  file: {
    pick(options?: FilePickOptions): Promise<File[]>
    save(data: Blob, suggestedName: string): Promise<void>
  }
  // 音频
  audio: {
    convertToWav(input: Blob): Promise<ArrayBuffer>
  }
  // 系统
  system: {
    platform: 'tauri' | 'web'
    openExternal(url: string): Promise<void>
    getAppVersion(): string
  }
  // 通知
  notification: {
    show(title: string, body: string): void
  }
}
```

### 平台检测与自动切换

```typescript
// platform/index.ts
import { TauriAdapter } from './tauri.adapter'
import { WebAdapter } from './web.adapter'

const isTauri = '__TAURI__' in window

export const platform: PlatformAdapter = isTauri
  ? new TauriAdapter()
  : new WebAdapter()
```

| 能力 | Tauri 实现 | Web 实现 (降级方案) |

| 系统托盘 | Tauri tray | 不支持 |
| 窗口管理 | Tauri window | 不支持 |

## 5. 功能模块设计

### 5.1 用户登录/登出

**流程**:
1. 启动时检查本地 Token 有效性 (解码 JWT 检查 exp) → 有效则自动登录，无效则显示登录页
2. 用户输入手机号 + 密码 → 调用 `Token/GetMemberToken` 获取 MemberToken
3. Token 安全存储 (桌面端: Tauri Store 加密存储，Web 端: localStorage + AES 加密)
4. 自动刷新: Token 过期前 5 分钟后台静默刷新
5. 登出时清除本地 Token、缓存状态、断开 WebSocket

**API 对接**:
| 操作 | API 端点 | 说明 |
|------|---------|------|
| 获取 AccessToken | `POST /Token/Get` | AppID 换取 AccessToken |
| 获取 MemberToken | `POST /Token/GetMemberToken` | 手机号+密码登录 |
| 刷新 Token | `POST /Token/RefreshMemberToken` | Token 过期前自动刷新 |
| 获取用户信息 | `GET /Member/Get` | 获取当前用户资料 |

**Token 刷新策略**:
```
Token有效期 ─────────────────────────────────────── 过期
                                    ↑ 过期前5分钟
                                    │ 触发 RefreshMemberToken
                                    │ 成功 → 替换本地Token
                                    │ 失败 → 重试3次,仍失败则跳转登录页
```

## 6. 安全设计

### 6.1 Token 安全存储

| 平台 | 存储方式 | 安全措施 |
|------|---------|---------|
| 桌面端 | Tauri Store (系统级加密) | 操作系统原生加密存储 |
| Web 端 | localStorage | 内容 AES-256 加密后存储 |

**Web 端加密方案**:
```typescript
// 使用 Web Crypto API 加密 Token 后再存储
const encryptedToken = await crypto.encrypt(token, derivedKey)
localStorage.setItem('auth_token', encryptedToken)
```

### 6.2 传输安全

| 措施 | 说明 |
|------|------|
| HTTPS | 生产环境强制 HTTPS |
| 请求签名 | 每个 API 请求附带 SHA-256 签名 (时间戳 + Nonce + Body) |
| Token 传递 | 通过 Authorization Header，非 URL 参数 |
| XSS 防护 | DOMPurify 过滤所有 Markdown 渲染输出 |
| CSP | Content-Security-Policy 限制脚本来源 |

### 6.3 密钥管理

| 密钥类型 | 存储方式 | 说明 |
|---------|---------|------|
| AES 加密密钥 | 桌面端: Tauri keychain / Web 端: 运行时派生 | 用于本地数据加密 |
| API 签名密钥 | 环境变量 (构建时注入) | 用于请求签名 |
| AppID/AppSecret | 环境变量 | 用于获取 AccessToken |

### 6.4 FunASR 安全访问

已实现: 前端通过 API WebSocket 代理访问 FunASR，内部服务地址不暴露。

```
前端 ──ws://api/api/Chat/FunASR?memberbearer=xxx──→ AgentBrook.API (MemberCheck 认证)
                                                      ↓
                                              ws://funasr:10095 ──→ FunASR Server
```

- 客户端通过 `services/voiceApi.ts` 构建 WebSocket URL，从 `secureStorage` 读取 Token 作为 query 参数
- 服务端 `ChatController.FunASR` 使用 `[MemberCheck(MemberToken=true)]` 验证会员身份
- `CommonApiBaseController.MemberToken` 属性已支持从 query 参数回退读取（兼容浏览器 WebSocket API 不支持自定义 Header）
- FunASR 服务器地址配置在 API 的 `appsettings.json:FunASR:ServerUrl`

## 7. 容错与重连机制

### 7.1 SSE 流式对话重连

```
SSE 连接断开
    ↓
检查是否在对话中 (有未完成的流式响应)
    ↓ 是
记录当前 messageId 和已接收长度
    ↓
指数退避重连 (1s → 2s → 4s, 最多3次)
    ↓ 成功
发送 resume 请求 (携带 messageId + offset)
    ↓ 失败
显示"网络断开"提示，用户可手动重试
```

### 7.2 WebSocket 重连 (语音/转写)

| 策略 | 说明 |
|------|------|
| 自动重连 | 断开后立即重连，指数退避 (1s → 2s → 4s → 8s → 16s → 30s) |
| 最大重试 | 10 次，超过后停止并提示用户 |
| 心跳保活 | 每 15s 发送 ping，超时 5s 无 pong 则判定断开 |
| 状态恢复 | 重连后恢复录音状态 (如果正在录制，继续发送) |

### 7.3 API 请求重试

```typescript
// services/http.ts - Axios 重试拦截器
const retryConfig = {
  maxRetries: 3,
  retryDelay: (retryCount: number) => retryCount * 1000, // 1s, 2s, 3s
  retryCondition: (error: AxiosError) => {
    return error.response?.status >= 500 || !error.response // 网络错误或5xx
  }
}
```

### 7.4 离线消息队列 (桌面端)

桌面端在网络断开时，用户发送的消息进入本地队列:
1. 消息存入 IndexedDB 离线队列
2. UI 显示"待发送"标记
3. 网络恢复后自动按顺序发送
4. 发送成功后移除队列并更新 UI

### 7.5 降级策略

| 场景 | 降级方案 |
|------|---------|
| API 不可达 | 显示离线提示，仅允许查看本地缓存的对话 |
| FunASR 不可达 | 语音功能置灰，提示"语音服务暂不可用" |
| SSE 不可用 | 回退到轮询模式 (每 2s 查询一次) |
| Token 刷新失败 | 3 次重试后提示重新登录 |

## 8. 性能优化方案

### 8.1 长列表虚拟滚动

使用 `@tanstack/vue-virtual` 实现消息列表虚拟化:
- 仅渲染可视区域 + 上下各 5 条 buffer
- 支持动态高度 (消息内容不等高)
- 滚动到顶部时触发加载更多历史消息

**性能目标**: 1000+ 消息场景，滚动帧率 ≥ 55fps

### 8.2 消息分页加载

| 策略 | 说明 |
|------|------|
| 初始加载 | 最新 30 条消息 |

## 附录 A: 发布注意事项

> 以下问题在 2026-05 发布过程中实际遇到，记录在此避免再次踩坑。

### A.1 跨平台 node_modules 符号链接

**问题**: macOS 创建的 `node_modules/.bin` 符号链接在 Windows NTFS 上无效，导致 `npm install` 报 `EINVAL` 错误。
**解决**: 发布脚本先删除 `node_modules`，如删除失败则重命名为 `_node_modules_old`，再用 `npm install --force` 全新安装。
**注意**: 不要在 macOS 和 Windows 之间共享 `node_modules` 目录。

### A.2 Windows 批处理文件必须使用 CRLF 行尾

**问题**: 用 macOS/Linux 工具创建的 `.bat` 文件默认是 LF 行尾，Windows `cmd.exe` 无法解析 `call :label` 子程序调用，脚本直接退出无输出。
**解决**: `.bat` 文件必须使用 CRLF (`\r\n`) 行尾。可用 `perl -i -pe 's/\n/\r\n/' file.bat` 转换。
**注意**: git 可能配置了自动转换 (`core.autocrlf`)，提交后 Windows 检出时应为 CRLF。

### A.3 Tauri 2.x 权限标识符格式

**问题**: Tauri 2.x 的 capabilities 权限使用 `core:` 前缀，如 `core:window:default`，而非 `window:default`。
**解决**: `src-tauri/capabilities/default.json` 中所有 core 权限必须带 `core:` 前缀。`tray:default` 不存在，托盘功能通过 tauri 的 `tray-icon` feature 内置。

### A.4 Rust/Cargo 编译目录不能在网络驱动器上

**问题**: W: 盘（网络/WSL 映射驱动器）不支持 Cargo 编译器的临时文件操作，报 `os error 87`。
**解决**: 设置 `CARGO_TARGET_DIR=C:\ZSN-AgentBrook-Build` 将编译输出指向本地磁盘。

### A.5 ARM64 Windows 需要 Clang 编译器

**问题**: `ring` crate 在 `aarch64-pc-windows-msvc` 目标上需要 `clang` 来编译汇编代码，纯 MSVC 不够。
**解决**: 安装 VS 的 "C++ Clang Compiler" 组件，或单独安装 LLVM。脚本自动搜索 VS 自带的 LLVM 路径。

### A.6 MSVC 环境加载时序

**问题**: `vcvarsall.bat` 会修改 PATH，如果加载太早会覆盖 Node.js 路径，导致 `npm install` 子进程找不到 `node`。
**解决**: 在 `setlocal enabledelayedexpansion` 之前调用 `vcvarsall.bat`，这样 `setlocal` 会保存完整环境。不要在 npm install 之后再加载。

### A.7 Visual Studio 版本目录名

**问题**: VS2026 (v18) 的安装目录是 `Microsoft Visual Studio\18`，而不是 `2022` 或 `2019`。
**解决**: MSVC 检测脚本用 `for /d %%y in ("%ProgramFiles%\Microsoft Visual Studio\*")` 遍历所有版本目录，不硬编码年份。

### A.8 macOS DMG 打包可能失败

**问题**: Tauri 的 `bundle_dmg.sh` 脚本在某些 macOS 版本上报参数错误。
**解决**: `tauri.conf.json` 的 `bundle.targets` 设为 `["app"]` 只生成 `.app`，跳过 DMG。桌面端产物为 `.app`（macOS）或 `.exe`（Windows）。

### A.9 ARM64 Windows 交叉编译 x64

**问题**: 开发机为 Apple Silicon Mac，Windows 虚拟机是 ARM64。Rust 默认编译 ARM64 二进制，在 x86_64 目标机上运行报错"映像文件无效，但它对另一种计算机类型有效"。
**解决**: `publish-win.bat` 中添加 `rustup target add x86_64-pc-windows-msvc` + `npm run tauri:build -- --target x86_64-pc-windows-msvc`。MSVC 工具链支持从 ARM64 交叉编译 x64。
**注意**: 指定 `--target` 后，Cargo 输出路径变为 `target/x86_64-pc-windows-msvc/release/`，需同步更新 NSIS/MSI 安装包的复制路径。

### A.10 Windows 目标机缺少 WebView2 运行时

**问题**: Windows Server 2022 等非桌面系统不预装 WebView2。Tauri 应用依赖 WebView2 渲染 UI，缺失时无法启动。
**解决**: `tauri.conf.json` 配置 `webviewInstallMode`:
- `downloadBootstrapper`: NSIS 安装时自动联网下载 (推荐，安装包小)
- `offlineInstaller`: 将 WebView2 离线包嵌入 NSIS (安装包约 196MB，适合离线环境)
- `fixedRuntime`: 将 WebView2 DLL 直接嵌入应用 (体积最大，最可靠)
**注意**: 仅 NSIS 安装程序会处理 WebView2 安装，裸 `.exe` 不会。

### A.11 静态链接 VC++ 运行时

**问题**: Rust 编译的 Windows 程序默认动态链接 VC++ 运行时，目标机可能缺少 Visual C++ Redistributable。
**解决**: 创建 `src-tauri/.cargo/config.toml`:
```toml
[target.x86_64-pc-windows-msvc]
rustflags = ["-C", "target-feature=+crt-static"]
```
将 CRT 静态链接到 exe 中，不再依赖外部 VC++ 运行时。

### A.12 NSIS 安装包文件名含空格

**问题**: NSIS 安装包文件名为 `ZSN AgentBrook_0.1.0_x64-setup.exe`（含空格），`if exist` + `copy` 通配符组合可能匹配失败导致未复制。
**解决**: 改用 `for /r` 递归搜索 `*setup*.exe`，自动处理路径中的空格。同时覆盖两个可能路径（带 `--target` 和不带），确保找到安装包。

### A.13 发布脚本结尾清理临时目录

**问题**: `npm ci` 前删除 `node_modules` 失败时会重命名为 `_node_modules_old_*`，多次构建后磁盘残留大量旧目录（每个数百 MB）。`CARGO_TARGET_DIR`（默认 `C:\ZSN-AgentBrook-Build`）也会积累大量 Rust 编译中间文件（数 GB）。
**解决**: `publish-win.bat` 在 `:win_summary` 之前统一清理 `client-app/` 下所有 `_node_modules_old*` 目录，并删除整个 `CARGO_TARGET_DIR`。

| 平台 | Web 版 | 桌面端 |

| macOS | `../Publish/ClientApp/` | `../Publish/ClientApp-Desktop/ZSN AgentBrook.app` |
| Windows | `../Publish/ClientApp/` | `../Publish/ClientApp-Desktop/zsn-agentbrook.exe` + `ZSN AgentBrook_*_x64-setup.exe` |
