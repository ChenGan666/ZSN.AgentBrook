## 🎯 项目概览

### 核心目标

ServiceDesk 是一个**面向客服场景的专用节点**，具有以下核心目标：

1. **快速响应** — 3秒内给出首次响应
2. **知识驱动** — 以知识库为第一数据源
3. **记忆感知** — 保持对话连续性
4. **兜底升级** — 无法处理时升级到 ClawAI
5. **通用可配** — 支持各种客服场景

### 与 ClawAI 的区别

| 维度 | ClawAI | ServiceDesk |
|------|--------|-------------|
| **场景** | 通用智能任务 | 客服问答/咨询/排查 |
| **响应速度** | 中等（规划→执行→反思） | 快速（检索→判断→生成） |
| **核心能力** | 多步骤任务规划与编排 | 知识库精准检索 + 上下文记忆 |
| **执行模型** | 规划-执行-反思循环 | FunctionCall 单次 LLM 调用周期 |
| **资源消耗** | 高（多轮 LLM 调用） | 低（单轮 LLM + 检索增强） |

## 🏗️ 系统架构

### 整体架构图

```
┌──────────────────────────────────────────────────────────────────────┐
│                     ServiceDeskAI 节点                               │
│                   (NodeType.ServiceDesk = 25)                        │
│                                                                      │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │                 ExecutionServiceDesk                           │  │
│  │                (节点入口，调度中心)                               │  │
│  │  ┌──────────────┐    ┌──────────────────────────────────────┐ │  │
│  │  │ 快速分类      │    │ FunctionCall 路径                    │ │  │
│  │  │ (问候/闲聊)   │    │ LLM + ServiceDeskKnowledgePlugin    │ │  │
│  │  │ → DirectReply │    │ → LLM 自主调用 search_knowledge_base│ │  │
│  │  └──────────────┘    │ → 流式输出 + 引用标注               │ │  │
│  │                       └──────────────────────────────────────┘ │  │
│  └────────────────────────────────────────────────────────────────┘  │
│          │            │             │                                │
│  ┌───────▼─────┐ ┌────▼────┐ ┌─────▼──────────┐                   │
│  │ Knowledge   │ │ Session │ │ Response       │  ← 核心能力模块    │
│  │ Plugin      │ │ State   │ │ Generator      │                   │
│  │ ([KernelFn])│ │(状态管理)│ │(FunctionCall)  │                   │
│  └─────────────┘ └─────────┘ └────────────────┘                   │
└──────────────────────────────────────────────────────────────────────┘
```

### 核心模块

| 模块 | 职责 | 性能目标 |
|------|------|---------|
| **请求分类器** | 快速判断消息类型（问候/闲聊 vs 需要检索） | < 150ms |
| **知识库检索插件** | [KernelFunction] 供 LLM FunctionCall 调用，文件级混合检索 | < 3s |
| **响应生成器** | FunctionCall 编排 LLM + 插件，流式输出 + 引用标注 | 首字 < 500ms |
| **会话状态管理器** | 管理多轮对话状态和意图信息收集 | < 50ms |

## 🚀 快速开始

### 开发环境要求

- .NET 10.0 SDK
- MySQL 8.0+
- Redis 6.0+
- Elasticsearch 8.0+ (可选)

### 依赖服务

| 服务 | 用途 | 必需 |
|------|------|------|
| **IHybridSearchService** | 混合检索 | ✅ |
| **IChatService** | LLM 调用 | ✅ |
| **IMemoryService** | 记忆管理 | ✅ |
| **IEmbeddingService** | 向量化 | ✅ |
| **Redis** | 缓存/会话 | ✅ |
| **MySQL** | 持久化 | ✅ |
| **Elasticsearch** | 全文检索 | ⭕ |

### 开发步骤

1. **克隆代码**
   ```bash
   git clone <repository>
   cd ZSN.AI.Node/ServiceDesk
   ```

2. **安装依赖**
   ```bash
   dotnet restore
   ```

3. **配置数据库**
   ```bash
   mysql -u root -p < scripts/create_tables.sql
   ```

4. **配置 Redis**
   ```bash
   # 启动 Redis
   redis-server
   ```

5. **运行测试**
   ```bash
   dotnet test
   ```

6. **启动开发服务器**
   ```bash
   dotnet run
   ```

### v1.2 (2026-05-06) - FunctionCall 重构

**架构变更**：将 `分类→检索→生成` 三步管线重构为 FunctionCall 单次 LLM 调用周期

- ✅ 新增 `ServiceDeskKnowledgePlugin` — [KernelFunction] 封装知识库检索，LLM 自主调用
- ✅ 重构 `ResponseGenerator` — 新增 `GenerateFunctionCallResponseAsync`，注入 IHybridSearchService
- ✅ 简化 `ExecutionServiceDesk` — 移除 IKnowledgeRetriever 依赖，非问候类统一走 FunctionCall
- ✅ 模型配置回退 — BuildModelConfig 优先使用节点配置模型，回退到系统默认模型
- ✅ 多轮对话支持 — 从 AppChatLogInfo 加载对话历史传入 ChatHistory
- ✅ 引用来源优化 — 检索结果携带知识库名/文件名，引用格式 `[知识库名] 文件名`
- ✅ System Prompt 优化 — 明确区分需要/不需要调用工具的场景，避免无效检索
- ✅ 更新 DI 注册 — 移除 IKnowledgeRetriever，更新 AutoJob 构造函数调用
