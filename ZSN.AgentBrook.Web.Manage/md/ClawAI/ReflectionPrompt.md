## 你的任务
请对照上方"任务目标"评估当前的执行情况，并决定下一步行动。

### 评估维度（必须全部检查）:

#### 维度1: 完成度检查（最优先）
在评估质量之前，必须先检查任务是否**真正完成**：

1. **对照原始任务的量化要求**: 原始任务要求生成N个结果，实际生成了几个？
   - 如果要求"生成3个分镜"，但只生成了1个 → 完成度不足，需要 replan
   - 如果要求"对每条数据进行分析"，但只分析了部分 → 完成度不足，需要 replan
   - 如果要求"N张图片"，但只生成了1张 → 完成度不足，需要 replan

2. **对照原始任务的功能要求**: 原始任务要求的每个功能点是否都已覆盖？
   - 如果任务要求"A+B+C"，但只完成了A → 完成度不足，需要 replan

3. **检查步骤输出**: 每个步骤的 expectedOutput 是否真正达成？
   - 步骤说"生成6个分镜"但输出只有1个 → 该步骤未达成目标

#### 维度2: 质量检查（完成度通过后再检查）
- 输出内容是否准确、相关
- 输出格式是否符合预期

### 行动选择原则 (必须严格遵守):

**重要: 知识库查询任务已获得结果后,必须选择 complete,严禁 replan!**
**重要: 迭代次数 ≥ 2 时,严禁选择 replan,只能选择 complete 或 fail!**

1. **complete** - 任务已完成，所有量化指标均已满足
   - 知识库查询任务: 已返回结果 → **必须选择 complete**
   - 其他任务: 已获得可用答案 且 数量/范围满足原始任务要求 → **选择 complete**
   - **不要**因为答案不够详细、不够完美就重新规划

2. **continue_execution** - 继续执行剩余步骤
   - 仅当还有未执行的步骤时使用

3. **retry_step** - 某个步骤失败,需要重试
   - 仅当步骤执行出错(如网络错误、超时)时使用
   - 重试次数 < 2 次

4. **replan** - 任务未完成，需要重新规划
   - ❌ **禁止**对知识库查询任务使用 replan
   - ❌ **禁止**因为结果不够详细就 replan
   - ❌ **禁止**迭代次数 ≥ 2 时使用 replan
   - ✅ **在以下情况使用 replan**:
     * **完成度不足**: 原始任务要求生成N个结果，但只生成了少于N个
     * **功能覆盖不足**: 原始任务要求的某些功能点完全未覆盖
     * 当前规划存在严重逻辑错误(如步骤循环依赖)
     * 步骤重复失败 ≥ 3 次且无法通过重试解决
     * 发现任务需求完全理解错误

5. **fail** - 任务无法完成
   - 仅当确实无法完成时使用

### 最终答案输出规则 (关键):
- **知识库查询任务**: 直接将返回的查询结果作为 finalAnswer
  - ✅ 正确: finalAnswer = 步骤的执行结果
  - ❌ 错误: 不要添加 "分析用户需求"、"推理分析结果" 等额外内容
- **不要**在 finalAnswer 中重复分析或推理,直接输出结果

### 决策流程:
1. **完成度检查**: 原始任务要求N个结果，实际有几个？ → 不足 → replan（如果迭代<2）
2. 检查任务类型: 是知识库查询? → 已返回结果? → **选择 complete**
3. 检查迭代次数: ≥ 2? → **不能选择 replan,只能 complete 或 fail**
4. 检查步骤状态: 有未执行步骤? → continue_execution
5. 检查步骤失败: 有失败步骤? → retry_step (重试次数 < 2)
6. 默认: **complete**

必须且只能输出标准JSON格式:

  "finalAnswer": "最终答案(如果 action=complete)",
  "retryStepIndex": 3,
  "refinedPrompt": "改进后的提示词"
}
